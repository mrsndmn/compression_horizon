# SPS paper and reproducibility bundle

The user requests a new committed `sps_paper` directory analogous to `paper/`,
documenting the completed Standard/SPS study, preserving reproducibility scripts,
and pushing the changes. This plan executes that authorized request on the current
feature branch. No new training jobs are required.

## Design

Use the existing ICML LaTeX style as a working preprint, with an independent main
manuscript, appendix, bibliography, figures, generated tables and build directory.
Keep the existing paper intact. The conditioning-interface result is central;
objective, routing, local geometry, generation and optimization-budget controls
bound the interpretation. Learned checkpoint differences and changed intervention
sites prevent an architecture-only attribution. Margins are not argmax errors.

Keep original experiment design in the existing Python registries. Save compact
per-sample evidence and measurement/provenance snapshots inside the new directory
so paper assets rebuild without the shared filesystem, checkpoints or a GPU.
Provide separate replay commands pointing to committed original experiment code
and its external checkpoint/token-cache prerequisites. Rendering must never submit
jobs. Record full job UUIDs and source commits. Reproduction is explicit about
external data/weights and about fixed-seed text bootstrap intervals.

## Ownership and interfaces

- Reproduction implementation: `sps_paper/reproduce.py`, `sps_paper/data/`,
  `sps_paper/tables/`, statistical figures, `tests/test_sps_paper_reproduce.py`.
  CLI contract: `export` reads existing artifacts; `render` consumes versioned
  snapshots offline; `plan` prints historical experiment replay commands.
- Manuscript: `sps_paper/main.tex`, `sps_paper/appendix.tex`,
  `sps_paper/references.bib`. Shared generated table basenames:
  `main_results`, `objective_factorial`, `budget_control`, `terminal_constraints`,
  `causal_routes`, `rescue`, optionally `lr_sweep`. Statistical figure basenames:
  `site_objective`, `budget_control`, `routes`, `terminal_constraints` (PDF).
- Parent integration: `README.md`, copied styles, `.latexmkrc`, `check.py`,
  root Makefile targets, guidance and tests/build/review/commit/push.
  Any deviations in generated asset names are coordinated before manuscript use.

## Implementation and verification

1. Add meaningful regressions for metric derivation, invalid/incomplete evidence,
   offline rendering and non-submitting replay-plan generation; observe failures.
2. Implement evidence export, audited derivation, paper assets and replay plan.
3. Write manuscript against source and actual results; verify external citations
   from primary sources. Distinguish observed causal effects from hypotheses.
4. Add build/check targets and documentation; regenerate all figures/tables,
   compile PDF, inspect rendered pages and check references/overfull content.
5. Run focused tests and the repository test suite (`pytest tests`, excluding
   duplicate archived checkouts from discovery), lint, and old-paper checks.
6. Commit explicit files, run a fresh portable adversarial review of the complete
   implementation, resolve findings, rebuild and push the current branch normally.
   Verify that the remote branch points to the resulting commit; never force push.

## Review focus

Metric provenance and per-sample alignment; historical versus current protocol
labels; positive-margin versus argmax failures; offline regeneration on a clean
checkout; replay commands and prerequisites; absence of implicit job submissions;
portable LaTeX references; no unintended changes or staging of existing files.
